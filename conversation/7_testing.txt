● I added the per-task time limit. The new offline test passes along with the
  other 51 tests (52 total). I haven't run it against the live app yet.

  How it works
  - Limit: each researcher task gets RESEARCH_TASK_TIMEOUT_SECONDS seconds, 180
    by default. Setting it to 0 turns the limit off.
  - At 70% of the limit: the researcher's tavily_search returns [TIME_LIMIT],
    which tells it to write its note now. A slow task can still leave a partial
    note.
  - At 100%:
    - The orchestrator stops waiting and sets a cancel flag. The abandoned
      researcher raises TaskCancelled at its next tool call, so it stops
      spending searches and tokens.
    - The task result becomes Notes file: NOT GENERATED - TIME LIMIT EXCEEDED.
      It tells the orchestrator not to retry and to carry on with the notes it
      has.
  - Report disclosure: the prompt requires the report to say which topic wasn't
    researched because of the time limit. This is enforced in code:
    save_final_report is refused until the report contains the words "time
    limit". The check works even if every task times out.
  - Parallel tasks: a timeout in one task doesn't affect the others, because
    each task has its own clock.

  Test: tests/test_time_limit.py uses a deliberately slow researcher. It checks
  that the orchestrator returns in about 0.5s, that an undisclosed report is
  refused, that a disclosed one is saved, and that the abandoned thread stops
  without writing a note.

    researcher-side checks.

    report check and the prompt step.
  - researcher.py (fin_agent/agents/researcher.py): one line in the prompt.
