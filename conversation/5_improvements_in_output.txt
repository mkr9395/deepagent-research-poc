● The main agent now verifies the final report against the original request as
  step 10 of its workflow, after saving the report and before replying. I didn't
  add a separate agent. Tests pass (50), and one live run called the check and
  passed.

  Where it happens

  plan → delegate → read notes → synthesize → completeness check (pre-write) →
  save_final_report
       → verify_final_report  ← NEW (step 10)
            ├─ no gaps → reply (step 11)
            └─ gaps → agent corrects the report → save_final_report → verify
  again (max 2 rounds)

  What I added
  - fin_agent/report_check.py (new, about 90 lines): a pure check_report()
    function made of keyword and structure checks, with no model call. It flags:
    - a requested company that never appears in the report;
    - a requested factor with no passage that names a company alongside it,
      which covers financials (revenue growth, profitability), risks and
      outlook;
    - missing source URLs, or fewer distinct URLs than companies;
    - a missing summary, comparison or Sources section;
    - no statement of uncertainty anywhere.
  - verify_final_report tool in orchestrator.py
    (fin_agent/agents/orchestrator.py): it takes no arguments. It re-reads the
    saved report from disk and original_request.md. It takes the requested
    factors from the request text as well as the plan's dimensions, so a factor
    the plan skipped is still caught.
  - Why a tool, not read_file: the request artifact is in outputs/, outside the
    sandboxed research backend, so read_file can't reach it.
  - Prompt, step 10: the agent is told to fix real gaps using only facts from
    notes it already read, or to state under evidence gaps that the item was not
    found. It must not start new research. The reply (step 11) says whether
    verification passed.
  - Logging: a VERIFY | ... | no obvious gaps or N gap(s): [...] line in the
    fin_agent.synthesis logger.

  Tests
  - Unit: one test shows a complete report yields no gaps. Another shows a
    report with a missing company, missing URLs and a missing Sources section
    yields those gaps, and that a factor requested only in the request text is
    caught.
  - Scripted end to end: the extended test saves a thin report, and verification
    reports "missing comparison section". The agent re-saves a corrected report
    and verification passes. The test checks that the corrected version is what
    ends up on disk.
